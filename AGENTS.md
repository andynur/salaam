# AGENTS.md — Learning OS

## Product

Learning OS is an internal HSI Boarding School platform for learning, assessment, projects, portfolio, gamification, attendance, calendar, and classroom operations.

## Stack

- Bun 1.4.2 baseline
- TypeScript strict
- React
- Tailwind CSS
- `Bun.serve()`
- PostgreSQL via `Bun.SQL`
- Bun native WebSocket
- local filesystem storage initially

## Architecture constraints

- Modular monolith.
- Prefer Bun/browser/PostgreSQL native capabilities.
- No backend framework by default.
- No ORM by default.
- No Redis/Valkey in V1.
- No microservices in V1.
- New dependencies require clear justification.
- Do not duplicate Activity engines: assignment, quiz, exam, survey, and challenge share the Activity domain.

## Security invariants

- Authorization is enforced server-side.
- Passwords use a secure Argon2id-based hash through Bun password APIs.
- Sessions use secure server-managed cookie strategy.
- File paths are generated by the application; never trust user filenames.
- Exam final submit must be idempotent.
- Server time is authoritative for exam windows.
- Student code must never execute directly in the main application process.
- Sensitive state-changing admin/grade/attendance actions should be auditable.

## Engineering workflow

Before coding:

1. Read this file.
2. Inspect only relevant source/docs.
3. Search for existing patterns before creating a new abstraction.
4. State a short implementation plan for non-trivial work.

During coding:

- Keep changes within requested scope.
- Prefer simple explicit code.
- Add migration for schema changes.
- Add/update tests with behavior.
- Reuse design tokens/components.

Before completion:

- Run targeted tests.
- Run `bun test`.
- Run typecheck.
- Run production build when relevant.
- Summarize changed files and tests.
- Mention unresolved risks only if real.

## Canonical commands

Use the commands defined in `package.json`. Keep these stable where practical:

```bash
bun install
bun run dev
bun test
bun run typecheck
bun run build
bun run start
bun run db:migrate
bun run db:seed
```

Do not invent alternate commands if existing scripts already cover the task.

For DB integration: `TEST_DATABASE_URL=postgres://localhost/hsi_learning_os_test bun test`.
The test database name must end with `_test`; tests use disposable schemas.

## Context and model use

- Keep task changes reviewable and commit-sized; do not dump complete files in chat.
- Run targeted tests first; inspect relevant files instead of ingesting the repository.
- Use the coding model selected by the user/IDE; never pin a model in repo config.
- Reasoning effort: low for mechanical work, medium normally, high for security,
  architecture, migrations, races, and complex debugging.
- Do not weaken sandbox or approval boundaries or grant broad tool/network access.
- Formatting: two-space indentation, semicolons, double quotes; TypeScript checks
  and focused review are the initial lint strategy. No formatter/linter dependency yet.

- Teacher/admin: Jira-inspired, dense productivity UI.
- Student: simpler, task/progress-focused UI.
- White/navy/blue dominant with golden accent.
- Reuse components and tokens.
- Every data view handles loading/empty/error state.
